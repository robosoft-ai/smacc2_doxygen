44// INTRODUCTION: Conceptually, AsynchronousClientBehaviors start in parallel on state entry.
45// Asnchronous client behaviors are used when the onEntry or onExit function execution could be too much slow and
46// could block the state machine thread.
47// AsynchronousClientBehaviors are related with the concept orthogonality of Smacc State Machines.
48// ASYNCHRONOUS STATE MACHINES DESIGN NOTES: Asynchronous behaviors can safely post events and use its local methods,
49// but the interaction with other components or elements of
50// the state machine is not by-default thread safe and must be manually implemented. For example, if some element of the architecture
51// (components, states, clients) need to access to this behavior client information it is needed to implement a mutex for the internal
52// state of this behavior. Other example: if this behavior access to some component located in other thread, it is also may be needed
53// to some mutex for that component
54// ALTERNATIVE: for long duration behaviors: using default-synchromous SmaccClientBehaviors with the update method
55
